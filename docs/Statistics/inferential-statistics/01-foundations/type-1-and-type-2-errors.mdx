# Type I and Type II Errors

A test compares two things: **reality** (which the world knows and you don't) and your **decision** (which you make from a sample). Each can go two ways, so there are exactly **four outcomes** — two right, two wrong.

- **Reality:** the null hypothesis is **True**, *or* the null hypothesis is **False**.
- **Decision:** you **retain** the null, *or* you **reject** the null.

## The four outcomes

Walking through every combination:

- **Outcome 1** — We **reject** the null hypothesis when in reality **it is false**. $\;\longrightarrow\;$ **Good.** (You caught a real effect.)
- **Outcome 2** — We **reject** the null hypothesis when in reality **it is true**. $\;\longrightarrow\;$ **Type I error.** (A false alarm.)
- **Outcome 3** — We **retain** the null hypothesis when in reality **it is false**. $\;\longrightarrow\;$ **Type II error.** (A missed effect.)
- **Outcome 4** — We **retain** the null hypothesis when in reality **it is true**. $\;\longrightarrow\;$ **Good.** (Correctly found nothing.)

| | $H_0$ **true** | $H_0$ **false** |
|---|---|---|
| **Retain $H_0$** | ✅ correct (prob. $1-\alpha$) | **Type II error** (prob. $\beta$) |
| **Reject $H_0$** | **Type I error** (prob. $\alpha$) | ✅ correct — *power* (prob. $1-\beta$) |

## Putting names to the mistakes

- **Type I error — the false positive.** Rejecting a *true* null: seeing an effect that isn't there. Its probability **is the significance level $\alpha$** you chose. Set $\alpha = 0.05$ and you've accepted a 5% false-alarm rate by construction.
- **Type II error — the false negative.** Retaining a *false* null: missing an effect that is real. Its probability is $\beta$, and it depends on how big the true effect is and how much data you have.
- **Power $= 1-\beta$** is the good twin of the Type II error — the probability of *detecting* a real effect. More data and bigger effects both raise power.

Back in the courtroom: a **Type I error convicts an innocent person**; a **Type II error frees a guilty one.** The legal system deliberately makes $\alpha$ tiny ("beyond reasonable doubt") because it judges convicting the innocent to be the worse mistake — at the cost of a higher $\beta$.

## The trade-off you can't escape

Here's the tension: **lowering $\alpha$ raises $\beta$.** Demand overwhelming proof before rejecting (tiny $\alpha$) and you'll acquit more of the truly guilty (bigger $\beta$). The *only* way to shrink **both** error rates at once is to **collect more data** — which sharpens the sampling distribution and pulls the two kinds of mistake apart.

Drag the significance level $\alpha$ below and watch the rejection region shrink: the false-positive rate drops, but a fixed real effect now needs to be even more extreme to be caught — power falls with it.

```python
import numpy as np
rng = np.random.default_rng(0)

# Simulate a two-tailed z-test of H0: mu = 0 at α = 0.05 (critical z = 1.96).
# Estimate the rejection rate when H0 is TRUE (Type I) and when it is FALSE (power).
def reject_rate(true_mu, n=30, sigma=1.0, trials=20000, crit=1.96):
    x = rng.normal(true_mu, sigma, size=(trials, n))
    z = x.mean(axis=1) / (sigma / np.sqrt(n))
    return np.mean(np.abs(z) > crit)

print(f"Type I error rate (true mu=0)   ≈ {reject_rate(0.0):.3f}   (target α = 0.05)")
print(f"Power             (true mu=0.4) ≈ {reject_rate(0.4):.3f}   (= 1 − β)")
```

## Why a quant cares

The two errors have completely different price tags, and which one hurts more depends on the seat you're in:

- **Type I = trading noise.** You deploy a strategy whose true edge is zero because the backtest looked significant. You bleed capital and costs on randomness. For a systematic fund launching strategies, controlling $\alpha$ (across *all* the strategies you tested) is survival.
- **Type II = the missed edge.** You reject a genuinely profitable signal because your sample was too small to clear the bar. No blow-up, but a real opportunity cost — and in a competitive market, someone else takes it.
- **Risk & compliance flip the priorities.** A fraud or blow-up detector would rather raise a false alarm (Type I) than miss a real disaster (Type II), so it *tolerates* a higher $\alpha$ to buy more power. Choosing $\alpha$ is therefore a **business decision about which mistake you can least afford**, not a statistical default.

There is no free lunch: the honest move is to name the costs of each error for *your* problem, then pick $\alpha$ — and a sample size — that respects them.

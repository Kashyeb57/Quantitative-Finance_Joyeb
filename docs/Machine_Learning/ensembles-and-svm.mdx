# Trees, Ensembles & SVM

For the **tabular** data that fills most of finance — a row per day or per company, columns of features — this family of models is the workhorse. Neural nets win on images and text, but on spreadsheets of factors, fundamentals, and technical signals, **tree ensembles and SVMs are usually the models to beat.** This page walks from a single decision tree up to the boosting methods that win most tabular competitions, then covers SVMs.

## 1. Decision trees

A decision tree splits the data with a sequence of yes/no questions — *"is the 10-day momentum &gt; 2%?"* — carving the feature space into rectangular regions and predicting a constant in each. Training is **greedy**: at each node it picks the split that most improves a purity score.

- **Classification** splits to reduce **Gini impurity** or **entropy** (how mixed the labels are).
- **Regression** splits to reduce **variance** (MSE) of the target within each region.

$$
\text{Gini} = 1 - \sum_k p_k^2, \qquad \text{Entropy} = -\sum_k p_k \log_2 p_k
$$

**Choosing a split on a numerical feature:** the tree sorts the feature's values, treats the midpoints between consecutive values as candidate thresholds, and greedily picks the threshold that most reduces impurity — one node at a time. A **regression tree** works identically but predicts the **mean** of the samples in each leaf and splits to most reduce **variance (MSE)**, producing a piecewise-constant fit.

A single tree is wonderfully **interpretable** — you can read the rules — but on its own it **overfits badly**: grow it deep enough and it memorizes noise. Its predictions have **low bias but high variance**. That weakness is exactly what ensembles fix.

## 2. Bagging &amp; random forests

**Bagging** (bootstrap aggregating) is the first fix: train many trees, each on a different **bootstrap sample** (a random resample-with-replacement of the rows), then **average** their predictions. Averaging many noisy-but-unbiased trees cancels the noise — variance drops, bias stays low.

A **random forest** adds one more trick: at each split, each tree may only choose from a **random subset of features**. This *decorrelates* the trees so their errors are more independent, which makes the average even better. Two free bonuses fall out:

- **Out-of-bag (OOB) error** — each tree never saw ~1/3 of the rows, so you get a validation estimate for free.
- **Feature importance** — how much each feature reduced impurity across the forest.

```python
import numpy as np
from sklearn.datasets import make_classification
from sklearn.tree import DecisionTreeClassifier
from sklearn.ensemble import RandomForestClassifier
from sklearn.model_selection import cross_val_score

X, y = make_classification(n_samples=800, n_features=8, n_informative=4, random_state=0)

tree   = DecisionTreeClassifier(random_state=0)
forest = RandomForestClassifier(n_estimators=200, random_state=0)

print("single tree    CV accuracy:", round(cross_val_score(tree,   X, y, cv=5).mean(), 3))
print("random forest  CV accuracy:", round(cross_val_score(forest, X, y, cv=5).mean(), 3))

forest.fit(X, y)
print("feature importances:", np.round(forest.feature_importances_, 3))
```

Run it: the forest beats the lone tree by several points, purely from **variance reduction** — same idea as diversifying a portfolio to cut idiosyncratic risk. (The first run downloads scikit-learn into your browser, so give it a few seconds.)

**In quant terms** — point a booster at next-day **direction** and read its feature importances to see which signals actually carry information. It's a crude but useful form of **factor discovery**:

```python
import numpy as np
from sklearn.ensemble import GradientBoostingClassifier

rng = np.random.default_rng(2)
n = 800
momentum = rng.normal(0, 1, n); rsi = rng.normal(0, 1, n)
volatility = rng.normal(0, 1, n); volume = rng.normal(0, 1, n)

X = np.column_stack([momentum, rsi, volatility, volume])
score = 0.9*momentum - 0.6*volatility + rng.normal(0, 1, n)   # only momentum & vol truly matter
y = (score > 0).astype(int)                                    # up-day?

gb = GradientBoostingClassifier(n_estimators=150, max_depth=2, random_state=0).fit(X, y)
for name, imp in sorted(zip(["momentum", "rsi", "volatility", "volume"],
                            gb.feature_importances_), key=lambda t: -t[1]):
    print(f"{name:11s} importance: {imp:.3f}")
```

Momentum and volatility rise to the top; RSI and volume are correctly judged near-useless. (Feature importance is a hint, not proof — always confirm out-of-sample, since a booster will happily "find" importance in noise.)

## 3. Boosting: learning from your mistakes

Bagging builds trees **in parallel** and averages them. **Boosting** builds them **sequentially**, each new tree focused on the errors the previous ones made. Done right, boosting turns many *weak* learners (shallow "stumps") into one very strong model.

- **AdaBoost** — after each round, **up-weight the misclassified points** so the next tree pays them more attention.
- **Gradient Boosting** — the general version: each new tree is fit to the **negative gradient of the loss** (for squared error, that's just the **residuals**). You're doing gradient descent, but in *function* space.
- **XGBoost / LightGBM / CatBoost** — fast, **regularized** implementations of gradient boosting. These are the default first choice for tabular problems and dominate Kaggle.

```python
import numpy as np
from sklearn.datasets import make_classification
from sklearn.ensemble import GradientBoostingClassifier
from sklearn.model_selection import cross_val_score

X, y = make_classification(n_samples=800, n_features=8, n_informative=4, random_state=0)

gb = GradientBoostingClassifier(n_estimators=300, learning_rate=0.05, max_depth=3, random_state=0)
print("gradient boosting CV accuracy:", round(cross_val_score(gb, X, y, cv=5).mean(), 3))
```

The key knobs are the **learning rate** (how much each tree contributes) and the **number of trees** — they trade off, and a small learning rate with many trees usually generalizes best. Boosting is powerful but **easier to overfit** than a random forest, so honest cross-validation matters even more.

**Classification or regression?** Every tree method here — a single tree, random forests, and *all* the boosting variants (AdaBoost, GBM, XGBoost) — has a **regression twin** (the `...Regressor` classes in scikit-learn). The algorithm is identical; it just predicts a **number** instead of a class, splitting on variance (MSE) rather than impurity. So the same toolkit forecasts *returns* as readily as it classifies *up/down days*.

## 4. Support Vector Machines

An SVM takes a different geometric view: find the hyperplane that separates the classes with the **widest possible margin**. Only the points on the edge — the **support vectors** — determine the boundary; everything else is irrelevant. A soft-margin parameter **C** trades off margin width against misclassifications.

The magic is the **kernel trick**: instead of manually engineering non-linear features, a kernel (e.g. the **RBF** kernel) implicitly maps the data into a higher-dimensional space where a straight hyperplane *can* separate curved boundaries — without ever computing the mapping explicitly.

```python
import numpy as np
from sklearn.datasets import make_moons
from sklearn.svm import SVC
from sklearn.model_selection import cross_val_score

X, y = make_moons(n_samples=400, noise=0.25, random_state=0)   # two interleaving crescents

print("linear SVM CV accuracy:", round(cross_val_score(SVC(kernel='linear'), X, y, cv=5).mean(), 3))
print("RBF SVM    CV accuracy:", round(cross_val_score(SVC(kernel='rbf'),    X, y, cv=5).mean(), 3))
```

On the interleaving-crescents data a linear boundary is hopeless; the RBF kernel handles it easily. SVMs shine on **small, clean, high-dimensional** datasets — but they scale poorly to huge samples and need careful feature scaling.

**SVR — the regression twin.** The same margin idea works for regression: **Support Vector Regression** fits a tube of width $\varepsilon$ around the function and only penalizes points that fall *outside* it. Errors inside the tube are ignored, which makes SVR robust to noise; with an RBF kernel it fits non-linear curves. In scikit-learn it's `SVR(kernel="rbf", C=..., epsilon=...)`.

## 5. Which one — and when (a quant's cheat sheet)

| Model | Strengths | Watch out for | Typical finance use |
|---|---|---|---|
| **Decision tree** | Fully interpretable, fast | Overfits alone | A readable first cut / rules |
| **Random forest** | Robust, little tuning, feature importance | Less accurate than boosting | Strong baseline; factor screening |
| **Gradient boosting / XGBoost** | Usually best on tabular | Overfits if untuned | Default-risk, return-direction models |
| **SVM (RBF)** | Great on small, clean data | Slow at scale, needs scaling | Regime classification on few features |

The models are the *easy* part. In finance the trap is **evaluation**: markets are non-stationary, so a plain random k-fold split leaks the future into the past. Use **time-aware validation** (walk-forward / purged CV), and treat a suspiciously high backtest score as a bug, not a discovery — see [Model Evaluation](/docs/Machine_Learning/model-evaluation) and [ML for Finance](/docs/Machine_Learning/ml-for-finance).

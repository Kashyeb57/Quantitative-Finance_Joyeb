# ML for Finance

This is the capstone — pointing everything from the rest of this section at real markets. The uncomfortable truth up front: **finance is the hardest domain to apply ML to,** and the failure mode is almost never a bad algorithm. It's a beautiful backtest built on a subtle mistake. This page is about the mistakes, and how to not make them.

## Why markets break the usual ML assumptions

Standard ML assumes clean, abundant, stationary data with a strong signal. Markets offer the opposite:

- **Tiny signal-to-noise.** A genuinely good stock-direction model might be **53% accurate.** Almost all of a return is noise; the edge is a whisper.
- **Non-stationarity.** The data-generating process *changes* — regimes shift, relationships decay. A model fit on 2019 can be actively wrong in 2020.
- **Adversarial & efficient.** Any edge you find, others are hunting too; publicizing or overusing it erodes it. The data fights back.
- **Short history, fat tails.** "Big data" in finance is often a few thousand daily observations, dominated by rare, extreme moves.

The upshot: **complex models overfit fast here.** A regularized linear model or gradient boosting with ruthless validation usually beats a fancy neural net on tabular signals.

## Financial feature engineering

Raw prices are useless to a model — they're **non-stationary** (a price trends; a model trained on \$50–\$100 fails at \$200). The first rule: **model returns, not prices.** Good features are stationary and leak-free:

- **Returns and log-returns** over various horizons; **rolling volatility**.
- **Technical indicators** (momentum, RSI, moving-average gaps) — but as *stationary ratios*, not raw levels.
- **Cross-sectional features** — rank a stock *relative to its universe today* (its return percentile), which is naturally regime-robust.
- **Alternative data** — sentiment scores, order-flow imbalance, macro surprises.

The **cardinal rule of every feature**: it may only use information **available at the moment of prediction.** A feature that peeks even one bar into the future will look magical and be worthless live.

## Labeling: what are you actually predicting?

The *target* deserves as much thought as the features. "Up tomorrow" is crude. Practitioner methods (see *Advances in Financial ML*, López de Prado, in the [library](/books)):

- **Triple-barrier labeling** — label a trade by which happens first: a profit target, a stop-loss, or a time limit. Far more realistic than fixed-horizon returns.
- **Meta-labeling** — let one model decide *direction* and a second model decide *whether to act* (bet sizing / confidence), which improves precision.

## The traps that wreck financial ML

1. **Look-ahead bias / leakage** — using data that wasn't available yet (a shuffled split, a feature computed on the full sample, restated fundamentals). The #1 killer.
2. **Backtest overfitting** — test 1,000 strategies and one will look brilliant by pure chance. This is [multiple testing](/docs/Statistics/inferential-statistics); the more you search, the more you fool yourself.
3. **Survivorship bias** — backtesting only on today's surviving companies ignores the ones that went to zero, flattering results.
4. **Ignoring costs** — spreads, slippage, and fees turn many "profitable" signals into losers. Always evaluate **net of realistic costs**.
5. **Non-stationarity** — assuming last year's relationships hold. Re-fit, monitor drift, and be humble about how long an edge lasts.

## Honest evaluation

Everything from [Model Evaluation](/docs/Machine_Learning/model-evaluation) applies, sharpened:

- **Walk-forward** validation only — train on the past, test on the future, roll forward. Never a shuffled k-fold.
- **Purge & embargo** — drop samples around each test window so overlapping labels don't leak.
- **Out-of-sample & out-of-period** — hold back a chunk of history you *never* touch until the very end.
- **Economic vs statistical significance** — a signal can be statistically "real" and still unprofitable after costs. The Sharpe ratio net of costs, not the p-value, is the verdict.

Here's the single most important lesson in one runnable snippet — how the *validation method* changes the story:

```python
import numpy as np
from sklearn.ensemble import GradientBoostingClassifier
from sklearn.model_selection import KFold, TimeSeriesSplit, cross_val_score

# A synthetic daily-return series with only a faint, real autocorrelation (weak signal + heavy noise)
rng = np.random.default_rng(0)
n = 1500
z = rng.normal(0, 1, n)
ret = 0.15 * np.r_[0, z[:-1]] + z                      # tomorrow depends slightly on today

X = np.column_stack([np.r_[np.zeros(k), ret[:-k]] for k in (1, 2, 3)])[5:]   # last 3 returns
y = (ret[5:] > 0).astype(int)                                                 # up-day?

clf = GradientBoostingClassifier(n_estimators=100, max_depth=2, random_state=0)
shuffled = cross_val_score(clf, X, y, cv=KFold(5, shuffle=True, random_state=0)).mean()
walkfwd  = cross_val_score(clf, X, y, cv=TimeSeriesSplit(5)).mean()

print(f"shuffled  CV accuracy: {shuffled:.3f}   <- flattered by leakage / look-ahead")
print(f"walk-forward accuracy: {walkfwd:.3f}   <- the number you can actually trust")
```

Even with a *real* signal baked in, the honest walk-forward number is modest — and that's the point. In markets, an edge that survives honest validation *and* costs is a genuine achievement, not a default outcome.

## The bottom line

The models in this section are **commoditized** — everyone has scikit-learn and XGBoost. The durable edge in quant ML isn't the algorithm; it's **better data, smarter features, careful labeling, and merciless evaluation.** Master those, stay suspicious of your own good results, and you're doing real quant work.
